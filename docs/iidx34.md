# IIDX 34 ZINRAI 适配

34 版的 `bm2dx.dll`（18,200,216 字节，2026-10-20）与 33 版结构保持一致，只是整体偏移变化。
插件现在按模块 `SizeOfImage` 自动选择地址表，**一个 DLL 同时支持两版**。

## 版本指纹

| 版本 | 文件大小 | `SizeOfImage` |
|---|---|---|
| IIDX 33 Sparkle Shower | 18,467,992 | 196,694,016 |
| IIDX 34 ZINRAI | 18,200,216 | 207,613,952 |

## 地址对照

| 项目 | IIDX 33 | IIDX 34 |
|---|---|---|
| cap 站点 ×3 | `0x827894 / 0x8279C1 / 0x827AEE` | `0x813DE4 / 0x813F11 / 0x81403E` |
| 雷达参数表 | `0x180CEF8B0` | `0x180CC4610` |
| finalize 入口 | `0x827610` | `0x813B60` |
| addBinary | `0xAD72B0` | `0xABD730` |
| 全曲重算 | `0x952DD0` | `0x939F00` |
| 2dxtra 写入函数 | `0x8820` | `0x9DB0` |
| 2dxtra call 点 | `0x919B` | `0xA49D / 0xA72B` |
| PNR 数组偏移 | `+0x36A8` | `+0x3718` |

## 定位方法（不依赖版本）

1. **cap 站点**：搜字节模式 `73 18 0F 2F D0 72`（`jae` + `comiss` + `jb`），应命中 3 处，
   且都在同一个 finalize 函数内。
2. **addBinary**：先搜字符串 `radar_score`，找 `lea r8, [rip+...]` 的引用点，
   再顺藤摸到 `call` 目标；其 prologue 是 20 字节的 4 条 `mov [rsp+...], reg`。
3. **雷达参数表**：搜连续 4 个 float `10.2 / 70 / 1.4 / 440`，表头是
   `1.2 / 1.25 / 1.75 / 2.2 / 300`，共 12 个 16 字节结构体。
4. **全曲重算**：从 `call finalize` 的调用点反查外层函数，序言特征为
   `push rbp / mov eax, 0x1660 / call ... / sub rsp, rax`。

## 34 版 2dxtra

34 的 2dxtra 是第三方 fork（5,249,536 字节）。它的写入函数、调用点形态与 33 一致：
`call` 之后直接 `mov r9,[r9]`，且调用点栈不对齐。因此沿用
"保存 r9/r10/r11 + `and rsp,-16` 动态对齐" 的跳板。

该功能仍是实验性的，默认关闭（`Enable2dxCompat=0`）。
